# ADR-001: DDD 기반 레이어드 아키텍처

## 상태

승인됨 (2026-04-04)

## 맥락

프로젝트 초기 단계에서 코드 구조를 결정해야 한다.
AI 코딩 에이전트가 코드를 생성할 때 올바른 위치에 배치할 수 있도록
명확한 구조가 필요하다.

## 결정

도메인별 패키지 구조를 채택한다.

- 각 도메인(user, post 등)은 독립적인 패키지
- 도메인 내부에 controller, service, dto, entity, repository 레이어
- 공통 모듈은 `global` 패키지에 배치

## 이유

1. **명확한 경계**: 도메인별로 패키지가 분리되어 책임이 명확
2. **에이전트 친화적**: AI 에이전트가 기능 추가 시 정확한 위치를 판단하기 쉬움
3. **독립적 개발**: 도메인 간 결합도가 낮아 병렬 개발 가능
4. **ArchUnit 검증 가능**: 레이어 간 의존성을 자동 테스트로 강제 가능

## 결과

- 모든 새 기능은 도메인 패키지 안에 레이어별로 배치
- ArchUnit 테스트로 의존성 규칙 자동 검증
- `global` 패키지는 도메인 공통 로직만 포함
